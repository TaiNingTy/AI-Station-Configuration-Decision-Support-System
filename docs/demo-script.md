# 5 分钟 Demo 讲解脚本 (Interview Script)

> 结构：问题(30s) → 洞察(30s) → 方案(1min) → 现场跑通(2min) → 评估与反思(1min)。
> 讲的时候强调"我是怎么想的"，而不是"我做了个 bot"。

## 0. 一句话开场
"我把在 Glydways 做站点系统设计的经验，抽象成了一个 multi-agent 的 AI 配置助手。它解决的是：站点配置知识分散在资深设计师脑子和文档里，导致标准不一、迭代慢。"

## 1. 问题 (30s)
- 用户：运营、工程、城市设计三个团队，标准不统一。
- 痛点：知识分散、规则靠人解释、方案反复改、一致性差。

## 2. 洞察 / AI Opportunity (30s)
"核心机会不是做聊天机器人，而是把**行业知识沉淀成可执行的 AI 工作流**。所以我的设计重点是知识工程 + agent 编排 + 人机协作边界。"

## 3. 方案架构 (1min) —— 展示架构图
"我用 3 个 agent 角色串成一个 pipeline：
① 需求分析 —— 从场地信息判断站点等级；
② 知识检索 + 规则校验 —— 挂了 4 类知识库(规划规范/工程约束/配置规则/历史案例)，做合规检查和风险识别；
③ 配置 + 文档 —— 给出带依据和置信度的配置方案，并生成交付文档。
中间我刻意保留了 human-in-the-loop：涉及工程可实施性和商业决策必须人工确认。"

## 4. 现场跑通 (2min) —— 录屏或实操
- 跑 **TC1 Greenfield**：展示完整闭环，指出"它识别了低洼排水风险，还复用了历史案例A"。
- 跑 **TC3 Central Hub**（高光）："这里曲线半径 27m 不满足工程硬约束，系统没有硬造方案，而是标红交还人工。这就是我说的 AI 与人的边界设计。"

## 5. 评估与反思 (1min)
- "我用 5 个维度 + 3 个用例做了评估，重点是硬约束场景。"
- 反思(展示成熟度)：
  - "现在知识库是精简版，真实产品需要和工程团队一起做知识治理；"
  - "下一步是接 GIS/CAD 数据，让需求分析从图纸自动抽取；"
  - "评估目前是人工打分，规模化要建自动化 eval 集。"

## 面试官可能追问 & 应答要点
- **为什么用工作流不用自主多智能体？** → "可控性和可评估性。企业场景里可预测比自主更重要，也更好定位错误在哪个 agent。"
- **怎么防止 AI 编造规范？** → "规则校验节点强制只引用知识库召回内容，并要求标注来源(KB编号)，输出里可溯源。"
- **哪些环节绝不能自动化？** → "工程可实施性判断和商业决策，我把它们设为强制人工确认点。"
- **这东西的价值量化？** → "目标指标是方案生成时间(天→分钟)、评审迭代轮次、配置采纳率。"
